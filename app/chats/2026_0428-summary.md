## New Node Types

### WebLink
New node type established and in use. Fields: `url`, `title`, `found` (surfing|recommended|received), `source`, `description`, `sparked`, `useful`, `tags`, `context_note`. Three nodes created this session. Parser does not yet handle `[web]` → WebLink automatically — Rex todo pending.

### FeatureRequest (as graph node)
`(:FeatureRequest)` node pattern formalized. Canonical pattern: planning doc in `app/planning/` + graph node + `[:FEATURE]` relationship from owning Todo(s). Aligns with Term definition. TOPS tracker is the first implementation of this pattern.

---

## New Relationship Types

### [:FEATURE]
`(Todo)-[:FEATURE]->(FeatureRequest)` — wires a todo to its feature spec. Allows multiple todos to reference the same spec. First used: TOPS tracker.

### [:REFERENCES]
`(Note)-[:REFERENCES]->(WebLink)` — note holds context and recommendation, WebLink holds the resource. First used: IANA link relations note → WebLink.

### [:REMINDER] 
Discussed. Pattern identified: `(Todo)-[:REMINDER]->(Note)` for attaching reference material to a todo without cluttering the notes field. Not yet implemented — deferred pending further design on Note vs FeatureRequest distinction.

### source_pin Convention Extended
`source_pin` field on graph nodes should point to the archive path of the originating file, not just the raw eml hash. Pattern: `E:\_Processing\archive\{filename}` or `MetaFileQueues\email\archive-instructions\{filename}`. Establishes traceability from node back to source document.

### contact vs buscard Distinction
`[contact]` tagged emails are general triage — may resolve to buscard, note, recommendation, or phone contact only. `[buscard]` is pipeline-bound (MFN). Parser currently routes `[contact]` incorrectly — Rex routing fix pending (`todo-1777394394941`). Contact folder in vera-queue is the correct holding area.

### FeatureRequest + Planning Doc Pattern
Canonical pattern for feature specs established: markdown spec in `app/planning/YYYY_MMDD-feature-{name}.md` + `(:FeatureRequest)` node in graph + `[:FEATURE]` relationship from owning Todo(s). Replaces cramming spec content into todo notes field.
