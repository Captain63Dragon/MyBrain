## Philosophy
MyBrain is a personal information OS on Windows. The filesystem is a dumb block store.
Neo4j is the authoritative layer. Files live on disk. Meaning lives in the graph.
The node owns its truth. The file is the delivery mechanism. Once value is extracted
into the graph, the file has done its job.

### Walled Garden
- **Wild** - unvetted, Dropbox/camera rolls. Prompts ingestion.
- **Garden** - curated, `E:\` subfolders. Ingested, named, backed up.
- **Node** - ground truth. Relationships, annotations. File-independent.

### The Divide
Browsers cannot access local filesystem. Docker has limited, explicitly mounted Windows access.
This is architecture, not a bug.

## MFI Protocol
File-based messaging bridging Docker and Windows. YAML files (.mfi), written atomically (.mft → .mfi).
```
/mfi/pending/     ← UI out-box, Windows in-box
/mfi/processing/  ← atomic lock
/mfi/completed/   ← Windows out-box, UI in-box (mfi_broker sole owner)
/mfi/email/archive-raw/   ← .eml source of truth
/mfi/email/vera-queue/    ← classified mail queue
```
Intent field is cargo - Windows handlers ignore it. Flask result processor branches on it.

### DiscoveryMFI - two modes
- **Directory scan:** `source` (dir path) + `patterns` (mask override, optional)
- **File list:** `files` (explicit paths) - skips scan entirely. `files` takes priority.

CopyMFI intents: `insitu_copy`, `master_source`, `master_target`
MoveMFI intents: `move`, `archive`

## Zaudi Sync Pipeline

Full design doc: `app/planning/2026_0420-feature-zaudi-todo-sync.md`

### Architecture
Two-sided sync between Neo4j (source of truth) and `api.zaudi.com` (mobile cache).
Zaudi is an inbox, not a database. Neo4j owns the record.

### PHP endpoint — `todo_sync.php` (deployed to api.zaudi.com)
Single endpoint, action parameter. Supersedes `push.php` for sync.
- `{"action": "get_unprocessed"}` — RENAME todos → todos_processing, CREATE todos_new, claim fresh rows, return fresh + stranded as Collection+JSON with rel links
- `{"action": "commit", "todos": [...]}` — bulk upsert into todos_new, DROP todos_processing, RENAME todos_new → todos
- Auth: `X-API-Key` header via `auth.php`
- Response: `application/vnd.collection+json` throughout
- `processing` column added to todos table: `ALTER TABLE todos ADD COLUMN processing DATETIME NULL DEFAULT NULL`

### Flask — `app/services/api_service.py` (new)
External API client. All Zaudi HTTP calls live here.
Key functions:
- `get_unprocessed_todos()` — POST get_unprocessed, parse fresh/stranded
- `commit_todos(todos)` — POST commit with full payload
- `get_todos_for_sync(limit=100)` — query Neo4j active todos, score+rank, return top 100
- `run_sync_cycle(reason)` — orchestrates full ingest + push. Re-entrancy guard via `_sync_in_progress`.

### Ingest cycle (Zaudi → Neo4j)
```
1. get_unprocessed → PHP begins lock, returns fresh + stranded rows
2. Flask: fresh rows → vera_todos_create (made_by='Vera') → success/failure lists
3. stranded rows → failure list directly (crash victims, no retry)
4. get_todos_for_sync() → scored + ranked active list from Neo4j
5. merge failures (synced_at=None) into payload
6. commit → PHP upserts todos_new, drops processing, renames to live
```

### Crash recovery
- `todos_processing` exists on startup → orphan detected, resume from step 1
- `processing` stamp on claimed rows prevents double-ingest on repeated crashes
- Crash between DROP and RENAME → narrow window, unprocessed items lost (acceptable)

### Call sites
- `base_routes.py` `/sync/zaudi/todos` POST — manual trigger
- `mail_ingestor._mail_ingestor_loop()` — fires after every poll, regardless of email count

### Guard — vera_todos_create during sync
`_sync_in_progress` flag prevents re-entrant push. Threading lock (`threading.Lock`) 
identified as needed — deferred post-validation.
